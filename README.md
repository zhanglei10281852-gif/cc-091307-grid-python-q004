# 小区燃气隐患闭环

服务于物业安全员、网格员、维修人员与社区管理者的燃气隐患闭环处置服务：
从“发现”到“销项”全流程留痕，异常分支可追溯，并发更新有版本保护，
离线补传不能推翻已完成结论，重启后未完事项继续计时。

运行环境：Python 3.11（仅标准库）。代码位于 `src` 目录，数据默认存 JSON 文件。

## 运行

```bash
python -m src.demo                       # 端到端演示（12 个场景）
python -m unittest discover -s tests -v  # 23 个单元/并发测试
```

## 领域模型与流程

严格状态机，非法跳转一律拒绝：

```
发现 discovered → 派发 dispatched → 上门 onsite → 复核
                                   ├─ 通过 → resolved → 销项 closed
                                   └─ 不通过 → re_review_pending → 再复核
派发/分支异常：
  dispatched ─ 住户拒绝入户 ─→ access_denied       ─ 协调后重新派发回 dispatched
  dispatched ─ 需更换设备   ─→ replacement_pending ─ 更换完成后回 dispatched
逾期：叠加标记 overdue_flagged + 系统事件，不冲掉主状态
```

- **登记**：人员角色与网格员所辖楼栋、住户授权范围（仅检查/检查+维修/可更换设备/拒绝）、
  设备状态与检测历史、隐患检查项与整改期限。
- **三个异常分支都强制留说明**：拒绝入户原因、设备更换原因、逾期后重新处置说明；
  设备更换还要校验住户授权范围。
- **只有复核通过才能销项**；复核必须附证据（照片/报告/签名单据编号），
  不通过必须写整改说明，整改后回到再复核。
- **重复派发返回原流程**：`dispatch_or_return` 不另起新单、不换责任人、不产生新版本，
  返回既有单据（`returned_original_flow=True`）。
- **版本冲突检测**：每个写操作携带 `expected_version`（乐观锁），
  服务端写区间由 RLock 串行化；过期版本抛 `VersionConflict`，不会后写覆盖先写。
- **离线终端补传**：携带终端基线版本与采集时间。隐患已复核通过/销项，
  或基线早于复核结论版本时，抛 `CompletedConclusionError`，结论不可覆盖；
  仍停在“已派发”则补传直接驱动到“已上门”；已过该节点则只追加留痕、不回退流程。
- **权限投影**：网格员只看所辖楼栋，视图隐去住户联系方式与全部复核凭证细节；
  维修人员只看派发给本人的单据；管理者 `manager_tracking` 可追踪
  责任人、逾期天数、每次复核证据与完整时间线。
- **重启继续计时**：逾期天数 = 今天 − 整改期限（实时计算），状态持久化在 JSON，
  进程重启后未完事项自动恢复并继续累计；复核通过/销项后逾期计时冻结。

## 代码结构

| 文件 | 职责 |
| --- | --- |
| `src/models.py` | 角色/授权/状态枚举、状态机流转表、住户/设备/隐患/检查项/复核证据模型 |
| `src/errors.py` | 领域异常：状态错误、版本冲突、完成结论保护、越权、重复派发等 |
| `src/storage.py` | JSON 原子写入存储与序列化，重启完整恢复 |
| `src/service.py` | `ClosureService`：登记、五步主流程、三个分支、补传、逾期、RBAC 视图 |
| `src/demo.py` | 端到端演示 |
| `tests/test_service.py` | 主流程、分支、并发、离线补传、权限、重启持久化测试 |
